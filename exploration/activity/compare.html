Agent and terminal status marks are stock library defaults on every surface today. Their ink boxes disagree, so a project sidebar row sits unevenly. Nine directions were drawn and eight retired; this is the one that survived, shown against what ships today.

Grid parity, adjacency and colourblind redundancy can only rule directions out. Meaning is what picks one, and the envelope is the only mark in the field that carries it.

On area, corrected. This page used to argue from enclosed area, which for a stroked glyph is the wrong measure: optical weight is ink length times stroke width. One mark, alone

Read this section first, and read it before anything else on this page. Every other cell here is comparative by construction: stacked rows, adjacency pairs, counters in fixed cells against a hairline datum. That is the right instrument for an ink-box question and the wrong one for a recognition question, because a mark that only fails with nothing beside it has no cell that can see it.

The board renders one mark on a card. Below is that card, with the real chrome read off the running desktop app, carrying one envelope and no sibling glyph, at the 14px the task card actually uses. Beneath each is the activity tooltip at 12px.

The envelope's box, and the flap angle that rides with it

The set exists because the stock marks disagreed: the loader and the terminal filled 18 x 18, the mail filled 20 x 16. The fix was to redraw on one box. What that round did not separate is that the mail was two things at once, wider and shorter, and only the width was ever costing anything. Ink width is what aligns the tabular counter column, because the ring's diameter is 18 and the chip is 18 wide. Height contributes nothing to that column.

So the candidates below hold width at 18 and vary height, except stock, which is the reference box drawn on this set's construction and the only candidate that moves the column at all. Without it there is no evidence either way about whether the alignment win is worth its cost.

Why the box and the flap are one decision

Flap ratios are fractions of the box, so transplanting them onto a box of a different aspect does not carry the angle across: the half-width moves with the width and the depth moves with the height. The angle is 2*atan((w/2)/depth), and it is what the eye actually reads.

This is the coupling the last round missed. It recorded that the selected flap "takes the reference glyph's flap ratios and puts them on this set's 18 x 18 box, so the angle is the reference's and the ink box is ours." The ratios carried; the angle did not. The reference glyph's V is 120.4 degrees; the same ratios on the square box give 108.8 degrees, which is 11.6 degrees pointier and sits only 4.5 degrees off deep, the draft that same round rejected as too pointy. This band measures one thing well: whether the counters line up. It cannot see a recognition failure, because every glyph in it has a neighbour and a datum. That is not a flaw in the band, it is its scope. The claim that used to sit here - that an ink box is only visible next to another one, so a mark alone is uninformative - generalised this band's scope into a reason not to look at a mark alone. The tests that can kill a direction

There are two adjacencies, not one. Idle renders beside working in every row where a project has both, so those two have to be told apart first. Then the pair has to stay clear of the Command Terminal chip, which lands in the same row roughly 22px away. Every cell below is at 14px, the size the sidebar actually renders.

The second adjacency is a meaning test, not a legibility one. A board agent is persistent and bound to a task; a Command Terminal is ephemeral and bound to a project. Those are different objects with different lifetimes, so a direction that lets one wear the other's silhouette leaves the row unreadable no matter how the colours land. The last column is that test at its hardest: both marks working, so both are green and both are marching, and only the interior is left to tell them apart.

The last two conditions are the ones that decide it. Motion off removes the marching dash; shape alone removes the colour too. A direction that goes blank in either column is carrying its state on one channel. Every cell is the same size, including the controls column, so what is being judged is the drawing rather than the placement.

Where each mark renders, and how big

Three things this settles. The controls spin a ring dashed 47 16, which on a circumference of 62.83 is 74.8 / 25.2: the app already picked the 3/4 chasing arc by hand, in two files, as a magic pair that breaks silently if the ring size changes. That is the drift this package exists to stop. A rotating dashed circle and a marching dashed circle are visually identical, so unifying on the march primitive costs these controls nothing on screen. And they use r=10, not this set's 18 ink box, deliberately, because lucide's Loader2 at r=9 "rendered ~10% smaller" beside them.

The risk this creates is specific: D4b's idle mark is a ring with a filled centre, and the stop control is a ring with a filled centre. One is an indicator with a count, the other is a button in a header, but they are the same drawing. D4c's double ring and D1's envelope have no such collision. D7 collides with the pause control deliberately, which is a different thing from colliding with it by accident.

On the size strip: the controls render at 20px and the row indicators at 14px because a header button is a target and a row indicator is a label. That is placement, not geometry. The drawing is identical at every size on that strip, which is the whole reason one ink box is worth having.

Motion

The Command Terminal already carries state without changing shape: colour plus a dash marching around its own border, normalized by pathLength="100" so the dash math is geometry independent. The question is whether the working state joins it or keeps the rotating arc it uses today.

Rotation is only coherent on a radially symmetric mark. D2a, D2b and D3 cannot use it: rotating an envelope or a chip is a tilt, not motion. Picking one of those picks the marching dash with it. Marching also removes the rotation transform on mobile entirely, which is what the frozen tilted-envelope guard in AgentStatusIcon exists to work around.

Portability, found while building this page: browsers honour pathLength on every shape, but librsvg and react-native-svg do not reliably, and a dash there silently falls back to user units, which on a 56 unit circle means a "75" dash covers the whole ring and the motion disappears. The geometry lives in one place, so it hands every runtime the number it can use. Resolved dashes: spinner ring 42.4115 14.1372, terminal chip null.

At rest

Reduced motion is a rendering, not a mute button, and stopping a marching dash does not land the same way on every silhouette.

Notes

Marks ship as currentColor only, so each surface applies its own tokens. Desktop is #e3b341 and #34d399, mobile is #d9b83f and #3ddc84, the website is #d98324 and #218a4c. The geometry never sees a hex.

Envelope flap: standard, on the shipped box depth 6.4458, vertex 108.8 degrees, settled 2026-07-28 from a six-variant study. Corrected 2026-07-29: that round recorded this as taking the reference glyph's flap ratios onto this set's 18 x 18 box "so the angle is the reference's and the ink box is ours". The ratios carried; the angle did not, because the box changed in both dimensions. The reference V is 120.4 degrees and the shipped one is 108.8, which is only 4.5 degrees off deep - the draft that same round rejected as a downward arrow rather than a flap. The rejected variants stay declared in lib/activity.mjs.

The set is five marks: two agent indicators, the terminal indicator, and the two controls. The controls were never candidates. They are the rest of the family, and they come in for the same reason the indicators do: the 47 16 dash they carry today is hand-computed and duplicated across two desktop files, so it breaks silently the moment the radius changes. On this set's grid that becomes the same pathLength 75/25 every other mark uses.

Two floors, not one. Indicators bottom out at 12px; the controls bottom out at 16px, because their centred glyph gets a fraction of an already small box and the pause bars merge into a single dot below that. Both render comfortably above their floor today, at 14 and 20.

The legibility floor for indicators is 12px. Below it the 2px stroke falls under one device pixel and the glyph smears, so a consumer rendering smaller uses a dot. The desktop terminal panel already renders at 8px and stays a dot.

On state channels, more precisely than I put it first time round. #e3b341 and #34d399 converge under deuteranopia, so colour alone is not enough. Motion is a real second channel and every one-silhouette direction has it, but it costs time to observe and it disappears entirely under reduced motion. Only a static difference is always present, and which directions have one falls straight out of their rest rendering, so this list is computed from the geometry rather than written down. Has one: D1. Has none: . For the second group the working mark has to drop its dash at rest, because a frozen 65/35 outline reads as torn, and dropping it lands on exactly the idle shape. With motion off they are one silhouette in two hues, and that is structural rather than a tuning problem. The shape alone column above is this same fact, rendered.
